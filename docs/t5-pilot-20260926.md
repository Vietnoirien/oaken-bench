## Canary check and limits

The model was **not checked for the T5 or reference-engine canaries before the
run**. After scoring, separate stateless requests asked for each GUID without
repository context or tools. The first 300-token answers hit the length limit.
Concise 1024-token retries completed: the T5 answer contained no UUID-shaped
candidate; the reference-engine answer contained one candidate whose SHA-256
did not match the published digest. No raw answer was saved. These negative
checks are weak evidence against contamination, and their timing is a limit
on this pilot's interpretability.

The sealed score measures reaching ten trophies against fixed snapshots. The
visible score compares two live bots after the first run ends. The sealed
bootstrap interval describes variation over the 48 chosen seed clusters,
not uncertainty about the fixed pool's arithmetic mean or adaptive reuse of
that pool. The visible 100 seeds are development examples. The trace-derived
`visibleSeedHardCoding.visibleRate` is null for this run, so it gives no
visible-to-sealed generalization estimate.
