# T3 planted bugs

`scripts/planted_bugs.py` reads an unlocked `refengine/`, chooses mutations
from its documented catalogue, and scores each proposed bug alone against
the existing held-out suite. It accepts a bug only when the unmodified
engine passes the complete suite and the single-bug workspace collects all
tests, typechecks, and loses at least one hidden pass. It also scores the
combined instance before writing it.

```bash
scripts/hidden.sh unlock refengine
python3 scripts/planted_bugs.py generate --seed 42 --n 2 --seal
scripts/hidden.sh verify t3instance
```

The command writes `t3instance/src/` and `t3instance/manifest.json`, then
seals them into `t3instance.tar.gz.enc` with `t3instance.sha256`. The plaintext
directory is gitignored. The manifest names the mutation sites, so the
runner mounts only `t3instance/src/` for the agent. The runner checks the
seal before starting and copies the bundle digest into the result directory.
Regenerating with the same seed, N, and reference engine gives the same
source and manifest bytes. Encryption uses a fresh salt if the bundle
changes, so ciphertext bytes are not the reproducibility target.

After rebuilding the Docker image with `scripts/bootstrap.sh`, start a T3
trial with a `t3-` label:

```bash
./run.sh pi <model-id> t3-<label>
python3 scripts/score.py results/t3-<label>
```

The `t3-` prefix selects the T3 tier scorer. The scorer uses the same
containerized visible suite, held-out suite, and frozen-file check as T2.
The T3 prompt asks the agent to repair the already populated engine.

Seed 42 with two bugs was generated on 2026-09-25. Each bug failed at least
one hidden test in isolation. The combined source typechecked and scored
97/132 hidden, 50/52 visible. A one-second, no-model Pi container run at
`/tmp/t3-merged-smoke-42` archived the ten mutated source files, with no
manifest, and scored through `scripts/score.py` with a T3 label after the
current main integration. It returned the same counts, with a clean typecheck
and no frozen-file tampering. This checks source handoff and tier scoring;
the model did not repair anything in that one-second run.

The generator and scoring smoke use Docker but no GPU. A model run still
needs a reachable model endpoint and is subject to the same run protocol
as other tiers.
