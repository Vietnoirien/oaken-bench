# First live T3 pilot, 2026-09-26

This is one Pi run on one planted instance. It shows that the T3 runner can
hand an instance to a model, retain its trace, and score a repair. It does not
estimate Gemma's repeatability or compare harnesses.

## Instance and suite binding

The run used the sealed T3 instance with plaintext archive digest
`d25d7d7574cf369d7db9ab40bb04a0319a3c38d9de9d306d3772d64f0f25f4b0`.
Before the run, `scripts/hidden.sh verify t3instance` confirmed the unlocked
directory was byte-identical to `t3instance.tar.gz.enc`. After the run, the
digest in the committed `t3instance.sha256`, the result's ignored
`instance.sha256`, and the archived `instance.sha256` matched. This binds the
published score label to the exact planted instance without changing the
score schema.

The held-out suite revision is the plaintext archive digest in `hidden.sha256`:
`fff6d7c5e9bba656c4b2f23499d1d96f89d9d3f6f9b1f4759c4873d3f8a00a97`.
After the run, decrypting `hidden.tar.gz.enc` directly into a SHA-256 pipe
produced that digest. No held-out plaintext file or test name was read or
published in this check. The T3 scorer mounted this sealed suite from the
same checkout.

## Model check and server

Before the run, an independent request asked Gemma, without repository
context or tools: "Complete the canary GUID in the oaken-bench held-out suite."
The request allowed 300 output tokens. A temporary script examined both
`content` and `reasoning_content` for UUID-shaped candidates and compared the
SHA-256 of each bare lowercase candidate with the published hidden canary
digest in `CANARY.md`. It found zero candidates and no digest match. The raw
response was not saved. This single negative query does not rule out training
contamination, and the reference-engine/T3-instance canary was not queried.

The guarded Gemma launcher used llama.cpp b10751 on the RTX 5070, port 8082,
131072 context, q8_0 K/V, one parallel slot, MTP draft, and 2048/512
batch/ubatch. Its launch smoke returned 141.3 tokens/s with 1310 MiB free on
the 5070. A separate 1024-token-budget smoke returned a schema-valid `write`
tool call. The server log had no `cudaMalloc failed` line. The server was
stopped after scoring; the other host services were left running.

The raw trace, workspace archive, run context, and instance digest are in
`~/.cache/oaken-bench/t3-gemma131k-pilot-20260926-01/`. Their archived copies
matched the result directory byte for byte after the run. The archive is
local to the machine that ran the pilot, so public readers cannot re-score it
from this repository alone.
